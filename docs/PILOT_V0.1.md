# DADO Retail — Pilot v0.1

Цель Pilot v0.1: безопасно запустить систему на отдельной тестовой кассе магазина ДАДО с реальными товарами и остатками, но без обязательного подключения реального банковского эквайринга до получения API/SDK провайдера.

## Обязательный контур

- PostgreSQL + DADO Retail API в Docker.
- Admin: товары, штрихкоды, цены, поставщики, приход, склад, инвентаризация, отчеты.
- POS: магазин/склад/касса, сканирование, серверная цена, контроль остатка, checkout, оплата, фискализация, списание.
- Возврат: проверка исходного чека и количества, фискальный возврат, возврат товара на склад.
- JWT/RBAC и аудит критичных операций.
- Health check и CI.
- Адаптеры платежного и фискального провайдера без хранения PAN/CVV/PIN.

## Внешние зависимости для боевого режима

Для реальных Card/QR и возврата денег требуется документация, тестовый endpoint и учетные данные банка/платежного провайдера. Для реального фискального чека требуется API/SDK конкретного фискального оборудования/оператора. Эти данные не должны храниться в Git.

## Gate перед установкой в магазине

1. CI полностью зеленый.
2. Чистая БД разворачивается миграциями.
3. Созданы тестовые магазин, склад, касса, пользователь и роли.
4. Проверены сценарии: приход → остаток → продажа → оплата → фискализация → списание.
5. Проверены: недостаточный остаток, повторная оплата, повторная фискализация, ошибка провайдера.
6. Проверен возврат полный и частичный без превышения проданного количества.
7. Проверены резервное копирование и восстановление PostgreSQL.
8. POS тестируется отдельной кассой и отдельным тестовым набором товаров до допуска к рабочей кассе.

## Статус

Backend, POS и Admin собираются в CI. Основной кассовый цикл и доменная модель возврата реализованы. Следующие блоки до Pilot gate: bootstrap/seed, тестовый provider mode, refund payment lifecycle, deployment/backup scripts, 1C Retail 2.3 exchange skeleton и сценарные integration tests.
